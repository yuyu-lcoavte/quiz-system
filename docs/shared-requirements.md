# 課堂搶答系統 — SpecKit / OpenSpec 共同需求

> 文件狀態：共同需求工作版本（已彙整討論決議，部分細節待確認）  
> 來源：課程《期末專題說明》、大組 HackMD 討論結果、後續補充說明  
> 共同需求主要維護位置：大組 HackMD。此檔為 SpecKit 專案使用的同步副本。  
> 重要：本文件區分「課程強制規定」、「大組已作決議」與「待確認事項」。不可以把待確認問題當成既定功能，或自行更改大組決議。

## 一、課程明確規定的需求

### R01 使用者角色
- 系統有老師與學生兩種使用者。
- 老師管理搶答，學生以組別為單位作答及提交。

### R02 Guided Notes 匯入
- 老師可以匯入 Guided Notes 題目；原始格式為 Google Sheets。
- 匯入題數須與 Guided Notes 一致。
- 不要求匯入題目敘述，僅顯示題號亦可。

### R03 搶答控制
- 老師可以開啟及結束搶答，並檢視搶答時的作答狀況及結果。
- 所有使用者的活動階段需要同步。

### R04 學生作答與搶答順位
- 學生在搶答開始後作答，以組別為單位送出答案。
- 最快搶答的組別被選定為搶答成功答案。
- 學生在搶答結束前不能看到其他組別的作答狀況，結束後可檢視結果。

### R05 Guided Notes 答案匯出
- 老師可將搶答成功組別的答案寫回原 Guided Notes 對應題目的填空格。
- 禁止將題號和固定儲存格位置硬編碼配對，因為會以另一份 Guided Notes 測試。

### R06 課程可選額外功能
- 匯入題組（多個題目須同時送出）。
- 將活動結果匯出 CSV（例如題號、組別答案、搶答順位）。
- 更公平的順位機制或其他改善功能。

### R07 開發與繳交
- 以 AI Agent 開發；SpecKit 和 OpenSpec 小組各有一個 GitHub Repository，功能需一致，需求變更需協調。
- SpecKit 組採用 Diagram First Development，須在 Specify 階段產出 PlantUML Component、Class、Sequence Diagram 的 `.puml` 檔，存放 `./diagrams/`，並使用 PlantUML CLI 轉出同目錄的 PNG；Plan 以圖為藍圖，Implement 後驗證程式碼與圖表一致。
- 不得公開密碼、金鑰或其他機敏資料；AI 自動測試之外仍需人工驗證。
- 可在本機模擬，不必架設公開伺服器。
- 每組一部 5 分鐘內 Demo 影片，須呈現老師端與至少兩個學生組別的完整流程。
- 繳交截止：2026-11-30 00:00。

## 二、大組討論已作的功能決議

> 以下依使用者提供的 HackMD「決議」欄整理，不再複製已過時的建議文字。模糊或互相矛盾之處列於第四節。

### 2.1 使用者與組別管理
- **Q01：進入系統**：老師經教師入口進入管理頁面；學生輸入活動代號進入活動。後續補充：**老師需以帳號、密碼登入**。共用首頁、分開入口是建議的 UI 呈現方式，尚非大組必要規格。
- **Q02：同組操作**：同組允許多人編輯；僅組長（第一位加入組別的人）能送出答案。
- **Q03：選組**：學生使用下拉選單選擇組別；以 Cookie 記錄相關選組資訊；搶答開始前可換組，開始後不能換組。

### 2.2 搶答活動流程
- **Q04：開始搶答**：老師有「開始」按鈕。
- **Q05：單題模式**：一般搶答一次開放一題；另有已選定的可選題組擴充，需能多題一起提交。
- **Q06：下一題**：老師可繼續下一題。
- **Q07：重新搶答**：老師可以重新開啟已結束的題目；重新搶答完成後，**直接以新結果覆蓋原本的搶答結果**，不需要提供舊結果的版本查詢功能。

### 2.3 作答與勝負判定
- **Q08：重複提交**：**同一組在同一題／同一輪搶答中，只能成功提交一次，不可重複提交**。提交之前可依 Q02 的多人編輯需求填寫答案；成功提交後不得再以同一輪再次送出。
- **Q09：最快順位**：由後端依有效提交到達／登錄順序決定。
- **Q10：空白答案**：純空白或僅有空白字元的內容不能提交。
- **Q11：近乎同時提交**：由後端處理先後順序，不採用學生端時鐘作為依據。
- **Q12：答案正確性**：不做自動批改。

### 2.4 Guided Notes
- **Q13：檔案方式**：由 Google Sheets 下載 Excel 檔案，使用者上傳 `.xlsx`，系統修改後匯出 Excel；此為大組選定方案，**仍建議向助教確認是否符合『匯出至原 Guided Notes』的評分要求**。
- **Q14：動態識別**：依題號格式、填空標記等方式動態辨識，不得寫死位置。
- **Q15：多個填空**：後續補充希望**一題每個填空格各有一個答案輸入欄位**。原 HackMD 寫「這就是題組」，與課程對「題組＝多道題一起送出」的定義不完全相同，需確認最終術語（見第四節）。
- **Q16：填空編號**：後續補充傾向保留原有的 `(1)`、`(2)` 等填空標記，並將答案寫回正確位置；原 HackMD 決議仍為「這啥」，故**尚待大組正式確認**。
- **Q17：修改範本**：大組決議「不用」，暫定不主動修改提供的 Guided Notes 範本；程式仍不得假設固定位置。

### 2.5 選定的額外功能
- **Q18：題組**：要做，但核心功能完成後再加。題組多題須全部填完才可一起送出，整組共用一個搶答順位；答案依個別對應位置寫回 Guided Notes。
- **Q19：CSV 匯出**：要做。
- **Q20：公平順位機制**：不做，保留最快有效提交者勝出的規則。

### 2.6 兩組協作
- **Q21：共用資料意義**：要統一題目、題組、填空格、組別、提交結果等邏輯資料定義；兩組實際技術與內部實作不必一致。
- **Q22：共用測試案例**：原決議「看需求」，具體案例及是否逐項共用**待確認**；但課程已要求各組自行驗證核心功能。
- **Q23：需求變更**：若有問題再討論；HackMD 是兩組需求的主要共同來源，有影響功能的決議應同步兩組各自的文件。

## 三、已選定功能的共同驗收方向

> 以下是根據課程要求與已決議功能整理的**建議驗收草案**；不表示 Q22 的詳細測試案例已經全部通過大組確認。

1. 老師以帳密登入，學生以活動代號加入並選組，至少兩個組別可參加。
2. 匯入另一份符合約定格式的 Excel Guided Notes，題數及填空對應正確，不依賴寫死儲存格。
3. 老師開啟前不能提交；開始後學生可作答，只有組長能送出，組員不能繞過前端提交。
4. 有效答案不得為純空白；後端正確決定提交順位，且同組同輪只能成功提交一次。
5. 老師與學生看到同步的活動階段；截止前學生無法取得其他組別的作答狀況。
6. 結束後可查看結果；老師能下一題、重新開題（直接以新結果覆蓋舊結果，不要求保留舊結果查詢介面）。
7. 勝出答案能依實際填空位置匯出至 Excel；原始題號、標記與格式處理方式以 Q16 最終決議為準。
8. 題組可同時提交多題、共用順位；CSV 可匯出活動結果。
9. 依共同規格完成 AI 測試與人工測試、SpecKit 圖表一致性驗證和完整 Demo。

## 四、需要再確認，請勿由 AI 擅自決定

- **U01／老師權限**：老師帳號如何建立與保管、是否支援多位老師、登入狀態如何維持？至少須驗證教師管理操作的權限。
- **U02／組長身分**：同時加入時誰是第一人、組長離線或重新登入怎麼辦、換組前後組長如何處理？
- **U03／多人編輯**：同組多人編輯的內容是否需即時共享？同時修改一格由誰的值為準？
- **U04／Q08 送出後編輯細節**：已確認不可重複提交，且提交前可依 Q02 編輯；若同組其他成員在成功提交後仍嘗試修改共用草稿，是否鎖定輸入欄位，屬介面／同步細節，須在學生端規格階段確認。
- **U05／Q07 重新開題技術細節**：已確認新一輪結果直接覆蓋舊結果；但舊提交紀錄、草稿及排名在資料層如何重置，以及系統如何辨識新一輪搶答，仍需在設計階段確認，以避免舊資料干擾新結果。
- **U06／Q15 與 Q18**：區分「單題多個填空格」和「多題組合提交」，決定使用的用語與資料模型。
- **U07／Q16 填空編號**：是否保留原始 `(1)`、`(2)` 及既有格式？答案是接在標記後還是取代標記？需大組確認。
- **U08／Q13 合規性**：請確認下載／上傳 `.xlsx` 後匯出是否符合助教對寫回原 Guided Notes 的要求。
- **U09／Q22 驗收細節**：兩組最終共用哪些測試案例，預期結果為何？
- **U10／題組資訊**：如何從 Excel 判定哪些題屬於同一題組，以及哪些欄位必填？參考範本，但不可寫死位置。

## 五、使用與維護約定

- SpecKit 專案中的 `docs/shared-requirements.md` 是 HackMD 已確認內容的本機副本，不應取代四人共用的 HackMD。
- 每次大組更動功能決議，應先更新 HackMD，再同步此檔與相應 SpecKit 規格／圖表。
- SpecKit 的 `constitution.md` 定義開發原則；此文件定義產品功能與共同約束。不要將兩者混為一談。
- 如果本檔與課程官方要求衝突，以課程要求為準並提出討論；如果本檔與最新大組決議衝突，以確認後的 HackMD 決議為準，再同步修訂。
