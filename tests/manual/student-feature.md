### 2026-11-12 單用戶端瀏覽器檢查

在 Windows 的 Codex 內建瀏覽器，以本機 Vite／Express 和新建的隔離 SQLite 操作。三個代號對應三場獨立的 Session。

| 項目 | 實際結果 |
| --- | --- |
| `DEMO-ACTIVE` | 以 `Demo QA` 加入既有「示範一組」，頁面顯示 Active、Round ID、組長資格、即時連線正常與兩題四個 Blank。未填齊時提交按鈕停用。 |
| 草稿與提交 | 儲存一格後重新整理，仍顯示原值、版本 1 及組長資格。四格填齊後提交成功，草稿版本 5，四個欄位唯讀；再次重新整理仍為唯讀。 |
| `DEMO-WAIT` | 顯示 Waiting 和「等待老師開始」，無題目輸入欄位。 |
| `DEMO-ENDED` | 以「示範二組」成員身分看到預先持久化的勝出組別「示範一組」及四筆成功答案。 |

尚待驗證三次全新身分加入計時、Cookie／CSRF 封包檢查、短暫離線後的同一 Participant 驗證、雙用戶端草稿同步／隔離，以及由正式 Teacher 驅動的階段轉換、換輪與結果。瀏覽器本次使用單一設定檔。

以下各項以實際操作結果填寫。記錄日期、Windows／瀏覽器版本、活動代號、組別、預期與實際結果；Cookie、CSRF Token 和其他憑證值須遮蔽。

## 2026-11-14 組長遞補新增驗收（待實作）

1. 以不同瀏覽器設定檔依序加入同一組 A、B、C。A 開兩個分頁，B 離線，C 保持在線。先關掉 A 一個分頁，確認 A 仍是組長；再關掉 A 最後一個分頁，確認伺服器偵測最後有效連線中斷後不加緩衝，直接讓 C 接任並更新其提交資格。記錄伺服器偵測時間，與使用者實際斷線時間分開。
2. 以同一瀏覽器恢復 A，核對 `/me` 的 Participant、Team 保持一致、角色已更新；A 舊畫面發出的提交必須被拒絕。C 可提交有效草稿一次。另測 A 僅一個分頁時按 F5 且 B 在線，觀察最後有效連線中斷是否先被偵測；若觸發遞補，A 不能靠重新整理取回角色。若仍有有效連線則不換人。
3. 讓組長在沒有其他合資格在線者時離線，再用同一憑證恢復。確認沒有強制任命，也沒有組長變更通知。另以不同組和 Session 的學生確認收不到變更事件。

2026-11-12 的單用戶端重新整理結果保留為舊版實測證據。本節及正式 Teacher 手動轉交與自動遞補的競爭均尚未驗收。

## T004 通過後的整合驗收

1. 以正式授權的 Teacher 後端與介面建立測試活動並控制同一 Session。讓至少兩個已加入的 Student 用戶端觀察 Waiting → Active → Ended、下一題和重新開題。正常連線下，記錄每個用戶端收到新 `stateVersion` 且畫面更新的時間，須在狀態變更後 2 秒內。確認新 Round 有不同 ID，舊草稿、提交與鎖定不沿用。
2. 使用有權限的 Teacher 操作指定同一 Team 的新組長，驗證權限交接、原組長失去提交資格及新組長可提交，並依審閱決議驗證手動轉交與自動遞補競爭。活動開始前由組長轉組仍須明確交接。
3. 在 T041／T044／T045 完成後，使用隔離的兩連線測試分別控制 Submission 和 End 先取得 SQLite 寫鎖。驗證 End 勝者取自同交易讀取、無勝者時無人工補造 Result、Result 於 Ended 廣播前已提交，並核對失敗回滾不廣播。瀏覽器另驗證 Ended 前讀不到勝出答案，以及有勝者／無勝者的顯示。
4. T059 完成介面比對後，於 T061 記錄正式 Teacher 與 Student 的實際操作、三次加入時間與初始組長重連結果。Demo 的三個代號對應獨立 Session，僅供分階段畫面驗證。Teacher End、老師轉交組長及同活動切換下一輪仍待整合驗收。
