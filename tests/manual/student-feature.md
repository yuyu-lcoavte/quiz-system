### 2026-11-12 單用戶端瀏覽器檢查

在 Windows 的 Codex 內建瀏覽器，以本機 Vite／Express 和新建的隔離 SQLite 操作。三個代號對應三場獨立的 Session。

| 項目 | 實際結果 |
| --- | --- |
| `DEMO-ACTIVE` | 以 `Demo QA` 加入既有「示範一組」，頁面顯示 Active、Round ID、組長資格、即時連線正常與兩題四個 Blank。未填齊時提交按鈕停用。 |
| 草稿與提交 | 儲存一格後重新整理，仍顯示原值、版本 1 及組長資格。四格填齊後提交成功，草稿版本 5，四個欄位唯讀；再次重新整理仍為唯讀。 |

以下各項以實際操作結果填寫。記錄日期、Windows／瀏覽器版本、活動代號、組別、預期與實際結果；Cookie、CSRF Token 和其他憑證值須遮蔽。

## 組長遞補 Windows 驗收

1. 以不同瀏覽器設定檔依序加入同一組 A、B、C。A 開兩個分頁，B 離線，C 保持在線。先關掉 A 一個分頁，確認 A 仍是組長；再關掉 A 最後一個分頁，確認伺服器偵測最後有效連線中斷後不加緩衝，直接讓 C 接任並更新其提交資格。記錄伺服器偵測時間，與使用者實際斷線時間分開。
2. 以同一瀏覽器恢復 A，核對 `/me` 的 Participant、Team 保持一致、角色已更新；A 舊畫面發出的提交必須被拒絕。C 可提交有效草稿一次。另測 A 僅一個分頁時按 F5 且 B 在線，觀察最後有效連線中斷是否先被偵測；若觸發遞補，A 不能靠重新整理取回角色。若仍有有效連線則不換人。
3. 讓組長在沒有其他合資格在線者時離線，再用同一憑證恢復。確認沒有強制任命，也沒有組長變更通知。另以不同組和 Session 的學生確認收不到變更事件。
4. 另用一場新的 Demo，先讓唯一在線的組長關閉最後分頁，再讓合資格組員上線。確認新上線者可接任，無須等待額外的遞補秒數。若原組長先恢復有效連線，則保留現有指派。

### 2026-11-14 T066 實測

使用 Windows、隔離 SQLite、Vite 5173、Express 3000 及 Codex 內建瀏覽器。A 使用 `127.0.0.1`，B 使用 `localhost`，兩個主機名稱各有獨立 Cookie。自行驗收時也可用 Chrome 和 Edge，或兩個獨立設定檔使用同一主機名稱。

- `DEMO-ACTIVE`：A 的兩個分頁都恢復相同組別與組長。關閉其中一頁後 A 仍是組長、B 仍是一般組員。關閉 A 最後一頁後，B 的角色自動更新為組長。A 以原 Cookie 開回活動頁時仍是原學生與組別，角色為一般組員。
- `DEMO-ACTIVE`：B 重新整理時，仍在線的 A 接任。B 回到原活動、顯示原學生名稱與一般組員資格。A 填完四格後提交，兩邊皆顯示草稿唯讀。
- `DEMO-WAIT`：唯一在線的 A 重新整理後仍為組長。關閉 A 最後一頁後，B 首次加入同組並連線，畫面顯示 B 已接任。

跳過離線／撤銷憑證的候選人、跨組／跨活動隔離、寫入回滾和提交交易順序由自動化測試驗證。這次瀏覽器以兩個 Cookie 身分操作，未執行三瀏覽器版本、封包時間量測或正式 Teacher 流程。T061 的三次加入計時及同活動切換輪次仍待整合。

Vite 在測試期間再次記錄 `ECONNABORTED`，上述操作均完成。遞補以伺服器收到 disconnect 的時間為準，瀏覽器重新整理與網路無回應時的偵測時間可能不同。

## T004 通過後的整合驗收

1. 以正式授權的 Teacher 後端與介面建立測試活動並控制同一 Session。讓至少兩個已加入的 Student 用戶端觀察 Waiting → Active → Ended、下一題和重新開題。正常連線下，記錄每個用戶端收到新 `stateVersion` 且畫面更新的時間，須在狀態變更後 2 秒內。確認新 Round 有不同 ID，舊草稿、提交與鎖定不沿用。
2. 在 T041／T044／T045 完成後，使用隔離的兩連線測試分別控制 Submission 和 End 先取得 SQLite 寫鎖。驗證 End 勝者取自同交易讀取、無勝者時無人工補造 Result、Result 於 Ended 廣播前已提交，並核對失敗回滾不廣播。瀏覽器另驗證 Ended 前讀不到勝出答案，以及有勝者／無勝者的顯示。
3. T059 完成介面比對後，於 T061 記錄正式 Teacher 與 Student 的實際操作、三次加入時間與初始組長重連結果。Demo 的三個代號對應獨立 Session，僅供分階段畫面驗證。Teacher End及同活動切換下一輪仍待整合驗收。
